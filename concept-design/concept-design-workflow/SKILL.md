# 概念设计协作

把参考和候选资产转化为可以继续制作的方案。入口独立于软件操作；有了概念方案，不等于已在工程中完成拼装、修复或出图。

## 模块规划与当前边界

概念设计包含多种工作，美术考究只是其中一个专题。先按用户本轮目标选择工作内容；跨模块任务可组合处理。以下为开放目录，不是概念设计的穷尽分类。

| 模块 | 当前状态 | 范围与后续完善方向 |
| --- | --- | --- |
| 美术考究 | 已沉淀当前偏好与方法 | 时代／题材适用性、参考出处、著名景观与物件辨识、可用判断和必要改造；见下方同名模块 |
| 氛围图 | 已预留，具体流程待后续讨论 | 围绕氛围图的分析、探索与修改积累需求；构图、光色、情绪等关注点按实际任务确定 |
| 细节改进 | 已预留，具体流程待后续讨论 | 围绕已有方案的局部优化积累判断和反馈方式；具体内容与验收标准按实际任务确定 |
| 概念脑洞联想 | 已预留，具体流程待后续讨论 | 围绕创意发散、联想和方案组合积累协作方式；不预先固定发散数量、套路或收敛标准 |

下方图片驱动协作、主动备选、镜头意识与保密要求是跨模块共用的现有偏好。美术考究的“能否用＋简短依据”回答格式只用于相应选型问题，不强制套到氛围探索、细节反馈或创意发散。需要判断具体参考的著名出处时，可以跨模块调用轻量核查，不因此把整个任务转成考据。

预留模块只登记方向，不表示已有完整技能或经过验证的流程。后续根据实际对话与任务逐步补充；有实质内容且篇幅需要时再拆到按需参考文件，当前不创建空文件或虚构经验。新需求也可以增补目录。

## 用户偏好的协作入口

用户明确偏好：**提供图片 → 助手识别、分块 → 判断各部分能否使用 → 给出组合方案**。在参考分析、选型和组合类请求中，以用户提供的图片为主要起点，优先回答“用哪些、怎样组合、改哪里”。不要求用户先掌握术语，也不以宽泛的知识讲解或大量外部搜索替代图上的具体判断。

图片足够支持初筛时直接推进。只有被遮挡或缺失的信息会实质影响选型、连接或制作时，才请求有针对性的补图；同时完成不依赖补图的判断。用户明确改为文字发散、严格考证或其他流程时，按本次要求执行。

## 美术考究

### 先沿用本次创作标准

从对话读取题材、用途、镜头主体、参考关系、精确程度和当前制作阶段；已有答案不要重复询问。

- **艺术化创作，允许无明显时代或风格冲突**：筛掉有充分依据的明显违和项；年代中性、来源不明但无显著冲突的形式可以作为候选。给出可推进的推荐，并将历史不确定性简短标明。
- **明确的风格或时代参考**：选少量有依据的样本，检查主要轮廓、构造、装饰和使用语境，不自动升级为学术复原。
- **明确要求严格复原**：提高来源与构造的证据要求，区分原物、后期修缮、复原图和现代演绎。

用户在任务中放宽标准后持续沿用，直到其要求改变。创作标准不是史实：无证据证明违和，不等于已证明属于某时代；有风格倾向，也不等于能精确定年。

### 简短选型回答与来源提醒

用户在创作语境问“这是某年代的吗”，默认理解为“能否用于该年代场景，有没有明显冲突”，而非要求精确定年。首句给出“可以用／需要改造后用／不建议用”；通常再用一两句指出主要原因或要找的造型方向。多候选用短表分别判断并选出首推项，不附长篇沿革。

- 简单考据只解决会改变选型的疑点。已有依据足够判断就停止；不能确认时简短标明，不用不断增加资料和免责声明替代可执行建议。用户明确暂停考据后，停止扩展调查，按已有信息与创作容忍度回答，除非用户随后要求核对新的出处问题。
- 著名来源核查是通用概念设计规则：对用户提供、准备采用的具体造型，主动做轻量、有针对性的公开出处检索，检查是否对应著名景观、建筑、器物、雕塑、角色或标志性设计，并提醒直接照搬造成的来源联想。不能把用户举出的风险例子当成当前图片的来源线索或预设结论，也不只在历史题材中执行。检索使用脱敏的可见特征，不自动上传未公开素材。
- 来源结论区分“已确认具体来源”“疑似某来源”“属于某种风格或谱系”“暂未查明”。插画、翻模或相似造型不足以断言直接来自某处；检索不到也不等于确认原创或没有著名出处。查到足以改变选型的信息就停止，不开启完整溯源。用户明确要求暂停所有检索时先遵从，以已有信息给出临时判断。
- 分清一般题材可用与某件成品可直接照搬。某种动物、神兽或装饰跨时代存在，不等于某个后期著名版本适合原样使用；反过来，也不因一个后期实例就否定整类题材。
- 不把曲线多、纹样密、尖角、金色、光滑或做旧程度当作单独的断代标准。无明确历史依据的修改，应表述为减少特定来源联想或改善本镜头的创作建议，不能包装为时代硬规则。
- 用户要搜实景图片时，提供具体的现存建筑／藏品名称、部位与可复制搜索词；只有术语或神兽名称不算满足请求。标清参考借的是形态、材料还是年代，古建筑本身的年代不自动证明现存附件同年代。

## 主动方案与参考使用

在用户的图片和组合想法上给出独立判断，指出更好的方案或有实质区别的备选及收益；尊重用户最终选择。只有缺少候选会明显影响筛选时，主动提出定向补图需求，例如“补几张接近候选乙的侧面照片”，不泛泛要求更多资料。

用户要多方案时，让主体轮廓、姿态、部件组合或装饰节奏真正变化，不仅改变胖瘦或颜色。用户认可的氛围图可作为创作主参考，实物参考负责补充局部；不要为了考据持续替换其已经接受的视觉目标。暗部和遮挡的结构标为需要设计补全。

图转三维的要求不等于抹平曲线和细节：通过完整视角、清晰受光、合理厚度与部件连接保证可读性。探索阶段可用方案对比板，选定后另出独立单体图；不要把方案拼图直接作为单体三维生成输入。

## 从图片识别到推荐

1. **确定画面中可见的内容。** 分清完整物件、局部构件、展示配件与环境。用通俗名称描述，必要时补术语；看不清的细节标为待确认，不用商品名称或搜索关键词替代识别。
2. **建立稳定编号。** 多候选图按位置编号；复合物件可再分主体、支撑、附件。需要图上说明时，用现有图片裁切、框选和标注，保留对应关系。不要把标注板称为已经合成的效果图。
3. **给出使用判断。** 可采用“优先基础、局部改造、暂不优先、信息不足”等标签。颜色表示选型建议；只有来源可靠时才用于年代分类。避免没有标准的精确吻合分数。
4. **落实组合。** 在已有候选中给出一个首推方案，明确部件来源、保留内容、必要修改与画面位置。只有有明显不同的视觉收益时再给少量备选，不用一长串等价选项把决策退回用户。

判断依据依次考虑用途和地域语境、整体比例、支撑与连接、材料及表面固定方式、装饰样式。做旧、颜色、饰物数量或单一纹样不能独立证明年代；商品模型可能混用不同来源的元素。

区分两种问题：**风格是否适合题材**与**模型是否经得起目标镜头**。低面数、模糊贴图、导入材质错误或缺少连接件，不自动成为年代判断的依据。

## 组合方案要能接起来

组合不是把几件喜欢的资产并列摆放。按实际可见范围检查：

| 关系 | 判断与调整 |
| --- | --- |
| 主体与支撑 | 支撑宽度、接触位置和视觉承重是否匹配；必要时调整托面、支腿或横撑，避免看似漂浮或压错部位 |
| 主体与附件 | 安装位置、朝向、尺度、连接方式是否成立；区分承重构件、固定件和纯装饰 |
| 不同来源的材质 | 木、皮、石、金属等材质身份清楚；统一所需色相、粗糙度与磨损程度，而非全表面同样做旧 |
| 主体与背景 | 背景通过轮廓和少量语境线索支持主体；避开切线、头顶长物、轮廓粘连及无意遮挡 |

用户问“有没有必要放某构件”时，分别回答它是否为结构或制度所必需，以及对本镜头是否值得采用。给出明确的创作建议和位置/形态依据，不把审美推荐说成历史规定。

## 按镜头分配细节与修改量

以用户指定的画面占比、景别和景深安排工作；不把某次占比、焦距或物件位置固定成通用参数。

- 主体特写优先看轮廓圆滑度、表面分辨率、边缘厚度、固定件、接缝和接触。用最终预期尺寸的局部图判断，远景预览不能证明特写合格。
- 虚焦背景优先看体量、朝向、疏密和可辨认的轮廓；虚焦仍会保留明显的题材冲突，不能当作通用遮错办法。
- 对用户允许艺术化处理的静态画面，镜头中的构成和可信度优先；画外细节无需等量深化。明确要求多视角资产、漫游或尺寸复原时，恢复相应约束。
- 区分镜头必改项和可后置润色项。先解决支撑、穿插、明显违和和近景质量，再考虑额外雕饰与细小旧化。

已有图片和原则足够决定首选方案时收敛，说明下一步具体要选取或修改什么。只有出现新证据或新需求才重开已解决的争论。

## 工具与执行交接

分析、裁切标注、方案建议和软件内实施分别说明。普通参考分析不自动启动软件、下载全部资产或生成成品模型。

用户要求在 Blender 中查看、拼装、修复或搭建时，转交本仓库的 [Blender 个人工作流](../../blender/blender-workflow/SKILL.md)，按其要求装载专题、核对当前工程并保留现场。将已选部件、镜头目标、必改项和待确认项带入操作，不在新阶段重置创作标准。其他软件采用当次可用的对应工作流。

需要补充历史或设计资料时，使用通用、不含保密上下文的检索词；实际读取来源后才声称已经搜索或核对。没有搜索能力时可以交付基于当前图片的判断，明确证据范围。

## 未公开项目与经验脱敏

用户指定项目未公开时，仓库中只保存通用方法和脱敏改写的情境。去掉项目名、人物或剧情、时间安排、文件路径、资产编号与来源链接、原始截图、水印、图像元数据以及能组合还原独特镜头的题材和物件关系。单纯把名称换成代号不足以完成脱敏。

不将原始项目素材或可还原的描述上传到外部服务。需要外部生成、图搜或其他上传操作时，先核对本次明确授权的素材与目的地。向技能库写入经验不包含提交、推送、发布或安装授权。

需要理解规则形成的原因或参考匿名方案表达时，读取 [脱敏情境与经验边界](references/anonymized-scenarios.md)。不为每次选型额外保存整段对话或制作日志。

## 完成标准

- 按本轮所属模块回答用户关心的问题；选型任务的可用判断、首选方案和必要修改清楚，其他模块不被自动转为选型或考据。
- 每个编号、标注和部件指向提供图片中的实际内容；截断部分没有被当成已观察事实。
- 区分可见事实、风格推断、创作推荐和已执行操作；不把未知年代强行归类。
- 修改量对应目标镜头，提供可进入下一制作阶段的具体方案。
- 声明实际完成范围。概念可行不代表组合已落地、严格史实已验证或最终画面已验收。
- 一般选型回答简短、明确；存在著名出处或后期制式联想时已提醒，并区分确证出处与风格相似。用户认可的创作方向没有被无止境考据或任意简化取代。

当前已沉淀图片选型的共用协作偏好与美术考究专题；氛围图、细节改进和概念脑洞联想仅预留位置，待后续共同完善。现有内容尚不构成跨项目的历史知识库或所有资产组合的实作验证。
