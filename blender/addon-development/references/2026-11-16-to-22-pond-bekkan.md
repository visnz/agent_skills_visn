# pond_bekkan 近期插件实践（2026-11-16 至 22）

历史案例，供同类开发按需读取；路径、按钮和参数以当前仓库为准。以下基于项目 开发计划 目录中的相应日期日志，不将一次性功能配置当成所有 Blender 插件的默认方案。案例主要覆盖 Blender 5.2.4 与 5.3.0；按材质 STL 仅有 5.3 后台小样，界面和切片结果留给用户验收。

## 节点、合成器与外部资源

- **5.2/5.3 合成器分支需要实机探测**：AutoBlend 在 5.2 使用 `Scene.compositing_node_group` 与 Group Output；5.3 原生 `Scene.compositor_effects` 可承载效果组，需保留现有效果顺序和原下游。场景实例或 RNA 属性表比对 `bpy.types.Scene` 直接 `hasattr` 更可靠。名称会变化的插口先核对 identifier；例如 Noise 的界面名由 Fac 改为 Factor，而 identifier 仍为 Fac。此结论来自两版本初始化、GUI 与渲染测试，不推断未来版本 API。
- **打包二进制资源按字节处理**：AutoBlend 的内嵌 .blend 节点资产不能走 UTF-8 文本补丁分支。构建时保留二进制内容与第三方来源/许可证，检查发行包内哈希及独立包的资源读取；注册阶段不加载场景资产。
- **文件选择器打开时锁定原目标**：Fab 最终版本向当前可编辑 Shader 树追加节点，不再造猴头或新材质。文件夹选择器期间用户可能退出组或改名；Operator 的 ID PointerProperty 在此处不可用，实测改用隐藏字符串保存材质和编辑树的 session_uid，目标被删除则取消。导入失败只回退本次新节点/图片并恢复原输出、选择和活动节点。实际文件名/分辨率比 Fab JSON 的源 URI 更能代表磁盘资源；选择同一分辨率的一整套贴图，避免混入其他资产。原先“新建猴头”的做法是旧阶段，不是当前实现。
- **暴露节点组接口会影响现有用户**：几何节点接口 `from_socket()` 复制设置后，已有外层组节点和修改器的新输入不自动继承当前值；要初始化新增参数，同时保留旧参数、已有连线和接口 Panel 层级。5.2/5.3 修改器输入实测走 `modifier.properties.inputs.<identifier>.value`。已有关键帧/驱动的默认值改为接线会令动画失效，因此跳过并报告；出错时撤销本轮新增接口、入口和用户属性。后台与真实 GUI 两版本均核对过结果和单步撤销。

## 只读检查要写清统计口径

- **可见性检查**：对象视图/渲染状态须合并对象、集合祖先、当前视图层与多重集合链接；多路径时不能只看第一条。排除词随 Scene 保存，扫描结果是上次快照，改隐藏状态或排除词后需重扫。没有测试逐动画帧、局部视图或相机射线可见性。
- **文件体积检查**：读最后保存的 .blend 文件，而非把当前内存数据当作磁盘体积。压缩工程可报实际磁盘大小，但类别占比只能按解压后的块字节统计，不能伪称各类压缩后精确大小。区分内嵌图片、外部图片、共享 Mesh 与独立复制；用户有未保存改动时明确提醒。5.2/5.3 以隔离样例复开、字节合计、GUI 绘制与不改变原数据的检查验证过；UDIM/序列整套外部体积和链接库依赖未覆盖。

## 按材质 STL：已验证的小样与待验收边界

当需求是“所选多个 Mesh 共用材质，按材质分文件，保持原世界位置”时，遍历**求值后面片**的材质索引，按 Material 数据块去重；未使用材质槽仅做非破坏式检查并忽略，不能把 Blender 的 Remove Unused 操作直接施加到原模型。对每个求值对象使用 `evaluated_get` / `to_mesh`，把三角面顶点乘求值对象的 `matrix_world`，最后 `to_mesh_clear`；不要逐物体归零、居中或改变选择。写临时文件再发布，不覆盖已有同名 STL，并检查输出三角数和世界坐标范围。STL 不含颜色，也不代表自动修复了闭合性或单位。

2026-11-22 的独立 Blender 5.3 后台小样：两个共用材质立方体与一个 Solidify 平面，共用材质导出 34 个三角面，另一材质 2 个；读回坐标范围与物体位置相符，原对象网格和修改器不变。之后补的“未使用材质槽计数”只做静态检查及源码/5.3 安装副本哈希核对。用户明确要求自己运行检查，因此 5.2 实机、3D 视图按钮和切片软件结果仍待确认；不要把前述小样表述成整项功能已验收。
