# Blender 插件仓库开发

对象是一个**插件的 Python 代码库**本身（operator、面板、注册流程、分支与协作记录），不是用户当前场景里的模型/材质/动画内容。后者属于 [blender-workflow](../blender-workflow/SKILL.md)。本技能记录的是在 pond_bekkan（蛙灾×桶桶双人维护的 Blender 5.2 插件）仓库中真实验证过的开发流程。

## 什么时候用

- 给一个已有协作规则的 Blender 插件仓库新增 operator、面板按钮或修 bug。
- 仓库里有 CLAUDE.md / AGENTS.md 一类文件，定义了"谁的模块不能随便改""改前要不要确认"。
- 需要在真实运行的 Blender（通过 MCP 或类似连接）里验证新 operator，而不只是语法检查。
- 遇到"按旋转物体算包围盒结果偏大""图标/事件枚举名不确定""多条分支改到同一处产生冲突"这类具体问题。

不适用：纯粹的 addon 打包/发行流程、从零搭建插件模板（这些交给社区 `blender-addon-development` 专题，见 [blender-workflow 的社区分流](../blender-workflow/references/community-routing.md)）；操作用户当前场景内容本身走 `blender-workflow`。

## 核心决策

### 1. 按当前项目判断改动边界

读取当前代码库的 AGENTS.md、CLAUDE.md 等适用规则，结合本次明确授权判断模块边界。只有当前项目确实要求额外确认、且现有授权未覆盖时，才说明触发条款、待改范围与影响并请求确认；不把 pond_bekkan 的模块协议复制给其他项目。新增文件也不自动豁免当前规则。

工作量、依赖或试错成本明显扩大时重新评估并反馈，不自动进入全量重构。[协作参考](references/repo-collaboration.md) 保留当时五要素、分支和留档经验，按适用条件使用。

### 2. 按任务选择分支与记录

先核对工作区与正确基点；分支、worktree 或当前分支内修改按项目约定和任务规模选择。不默认 stash、移动、重置或提交用户已有改动。任务无关改动保留，确需隔离时先说明方案；用户已经授权的范围直接完成。

合并只在本次授权包含时执行。冲突按语义保留双方有效功能，不机械拼接两边。项目要求开发记录时沿用其目录和格式；否则简要交付说明即可，不为每次小改动新建日志。

### 3. 按改动风险选择验证

纯文档或独立计算修改不要求连接真实 Blender。涉及 bpy API、注册、operator 或 UI 上下文时，选择相关静态检查、隔离后台测试和必要的交互端到端测试；后台检查不能证明真实交互分支通过。只有实际合并时才验证合并后的组合，不要求每项任务都合并或重载。

需要实际 Blender 操作时，按需读取 [现场工作流](../blender-workflow/SKILL.md) 与相关社区专题；本技能主导代码维护，不要求为此加载所有场景资料，两入口不循环全量加载。

### 4. 测试时保护用户现场

优先隔离工程/实例。确需当前连接时，确认目标工程、模式、选择与未保存状态；使用本次新建且身份明确的测试数据，不按名称前缀删除用户原有内容。测试可恢复时还原选择、活动对象和游标。用户正在编辑时不强切模式；未覆盖交互分支如实说明。

有写入的调用中断后先重读状态，再只补缺失步骤，不盲目重放。上下文与连接细节见 [现场测试参考](references/mcp-live-testing.md)。不自动重载、安装或保存用户工程。

### 5. 按任务触发的 bpy 技术陷阱

- **带恢复语义的开关要核对状态寿命**：插件支持代码热重载时，模块级字典可能在用户关闭开关前清空。让恢复快照在预期的重载流程中仍可取得，按钮状态以实际快照为准；丢失快照后不要猜测原设置。适用条件、验证顺序及案例见 [热重载状态参考](references/reloadable-ui-state.md)。
- **批量处理共享数据块要说明影响范围**：从选中对象的材质槽收集材质时先去重，再核对未选中对象是否也引用相同材质；按对象选取目标不等于修改只影响该对象。
- **图标/枚举名用前查，不凭记忆**：不同版本/图标集合未必包含某个名字；用当前连接的 Blender 实际查询枚举（如 `bpy.types.UILayout.bl_rna.functions['prop'].parameters['icon'].enum_items`，事件类型查 `Event.bl_rna.properties['type'].enum_items`）确认存在再写进代码。
- **世界空间包围盒不能用局部 bbox 整体变换**：物体局部空间包围盒（`obj.bound_box` 的 8 个角点）本身对圆柱等非箱形几何就比真实形状宽松；物体一旦被旋转，把这 8 个角点整体乘 `matrix_world` 再求 min/max，就是"盒子套盒子"，算出的世界空间范围会比真实几何更大。需要贴合物体实际旋转/缩放表现的边界时，要逐个真实几何点（mesh 顶点、曲线端点+贝塞尔手柄）变换到世界空间后再求 min/max。技术细节、验证数据和案例见 [references/world-space-bbox.md](references/world-space-bbox.md)。

## 完成标准

- 说明实际改动、当前项目要求及已满足的协作条件，不重复索取已覆盖的授权。
- 实际使用分支、合并或项目留档时报告相应结果；未涉及的阶段不强制执行。
- 按本次变更验证相关功能，区分语法、计算、后台和真实交互测试；未覆盖的 API/模式/分支明确说明。
- 使用真实场景时核对本次测试数据已清理、必要现场已还原；文件保存、插件安装、重载和发布分别依授权处理。
- 技术陷阱按实际功能触发，图标/枚举或几何边界没有改动时不额外测试；案例方法不能代替当前版本与目标几何的核对。
