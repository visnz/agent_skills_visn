# 摆姿势前遇到导入骨轴异常

仅在“骨头好像统一转了 90°”、旧修复脚本失效、或现有姿势需要保留时读取。目标是先判断骨轴问题，避免在方向混乱的骨架上继续摆姿势；完整导入/动画兼容任务应另行处理。

1. 查骨架物体世界变换、每根静止骨的头尾与 `matrix_local`、当前姿势矩阵、约束、驱动、动画和绑定网格。Blender 骨头局部 Y 轴沿头到尾；物体整体旋转、显示形状/骨 Roll 与静止骨方向错误不是同一问题。不要因为看到 90° 就清零物体旋转，或给所有姿势骨统一加 90°。
2. 新导入 FBX 时，先查当前 Blender 版本和实际 `bpy.ops.import_scene.fbx`、`bpy.ops.wm.fbx_import` 的 RNA 属性。旧导入接口可能有 `automatic_bone_orientation`，另一个接口可能没有；仅在当前运行时确认后使用，不推断必须安装 Better FBX。自动定向的分叉、末端和辅助骨仍需检查。
3. 对已有且要保留当前姿势的骨架，可重定向静止骨，同时补偿姿势。所有矩阵在同一骨架空间：旧静止矩阵 R、旧姿势矩阵 P、新静止矩阵 R₂，则保持蒙皮变形的目标为 `P₂ = (P @ R.inverted()) @ R₂`。先完整捕获旧矩阵，再批量建立目标并转换回每根骨的 `matrix_basis`；别在改完父骨后才读旧子骨矩阵。
4. 同帧比较修改前后求值网格的顶点数量与世界位置，并检查目标骨链方向、当前姿势和隐藏模型。该公式不能自动保证约束、驱动、B-Bone、动作曲线、骨骼父级附件或导出兼容；需要保留动画时另行转换/烘焙并跨帧验证。

摆姿势只需要可控的骨架和可信蒙皮。若用户目标是导出到原系统或保留完整动画，应先确定兼容方案；不要把这一步默认为静态摆姿势的一部分。
