# Blender 个人工作流

以用户当前选中的内容、正在使用的工程和明确指定的资产库为起点。用户说“这个节点”“另一个工程”时，先读取现场，不让用户重复提供工具可以取得的信息。

## 开始前：判断任务范围与社区加载需求

仓库只维护个人规则、社区索引和下载器，不保存第三方技能源码。本入口是调度层。先粗估操作范围、资料装载和验证成本；预计批量处理、长时间渲染/模拟或反复试错时先反馈方案，范围明显扩大时重新评估。

只读查询、版本/连接/选择检查以及任务规划可先使用现有工具，不要求为此联网下载；需要技术资料时再加载基础或相关专题。修改工程、保存/导出、渲染/模拟或执行有副作用的 Blender 脚本前，默认完成以下加载。只读脚本按其实际行为判断，不能仅因使用了 execute_code 就视为修改。

1. 分析用户要做的阶段和交付物，按 [references/community-routing.md](references/community-routing.md) 选择真正相关的专题。只读场景查询不强制下载基础技能；需要基础资料时只加载 core，不因出现“角色”就自动执行绑定或重拓扑。
2. 运行 [scripts/prepare_community_skills.py](scripts/prepare_community_skills.py)，指定选中的技能；脚本自动带上 `blender-core`。下载固定 commit 的技能、配套参考、脚本与许可证到**仓库外缓存**，不运行下载代码，不修改全局技能或 MCP 配置。网络和缓存写入依照当前环境权限执行。
3. **真正读取**脚本返回的 `load_order` 文件，顺序为 `blender-core/SKILL.md` → 所选专题 → 当前个人 `SKILL.md`。下载成功、安装完成或只看到名称，都不算已经加载指令。专题再引用其他技能时，按实际需要补充下载并读取。同一任务已读取相同版本的基础/专题时记录状态，不因最后重读个人入口而再次进入下载循环；仅补充新增阶段所需内容。
4. 最后落实本文件的个人要求，以及本次任务需要的个人参考；然后检查真实 Blender 版本、连接、选择、源与目标，开始操作。社区技能提供通用技术方法，本次用户指令、现场数据、个人路径/参数保留与授权边界优先；不能据社区示例擅自清空场景、统一比例、发布插件或修复全库。

在当前技能目录下调用（所有仓库内路径都相对此目录，不依赖作者用户名）：

```text
python scripts/prepare_community_skills.py --list
python scripts/prepare_community_skills.py --skills blender-scene-setup blender-pbr-materials
```

第二条示例适合节点资产整理；基础技能自动加入。脚本输出 JSON 包含绝对缓存路径与读取顺序。默认缓存位于系统临时目录，可用 `--cache-dir <仓库外可写目录>` 指定持久缓存；`--offline` 只使用已校验缓存。默认不追随上游 main，版本和哈希记录在 [community-skills.json](community-skills.json)。

只读取本地 skill 文件就可以完成装载，无须把全部专题全局安装到宿主。若运行环境有原生技能加载功能，可加载返回路径；否则直接读取文件及其按需引用的参考，具有相同的指令输入作用。它不会凭空提供 Blender/MCP 工具。

网络不可用但固定版本缓存完整时，校验并离线读取后继续。缓存缺失、哈希异常或社区版本不适用于现场时，如实说明缺口；可继续现有工具支持的独立只读查询和规划，暂停依赖缺失资料或能力的修改、保存、导出、渲染/模拟步骤。不要将普通知识或另一份未审阅资料冒充已完成社区加载，也不自动升级来源、安装运行时或修改全局配置。兼容方案需先核对现场和资料，说明替代依据及验证范围；必要的用户选择不重复询问。

## 按本次实际需求工作

- “节点单独入库”意味着可复用的节点组资产；“合并进资产库文件”意味着将数据追加到指定主 `.blend` 并保存。临时导出文件只是中间产物，不能当作已经完成合并。
- 区分组接口默认值、实例参数和外部连接/驱动值。按用户本次要求选择参数来源：明确保留组默认值时不以实例覆盖；明确保存当前效果时核对实例值。只在导出副本中调整，不把某次入库的选择推广到所有资产。
- 完整资产入库默认处理现有分类和缩略图；用户明确只要求检查、追加或暂不制作预览时按本次范围执行，不扩展任务。需要缩略图时优先制作能说明效果的 Blender 渲染预览，查看实际图像后再嵌入资产。
- 用户要求操作时，完成已经授权的检查、复制和验证。只有目标或内容确实无法确定时再提问；必要的权限申请遵守运行环境要求。
- 上述做法来自已发生的资产入库需求。不要据此擅自重整整个资产库、删除其他资产、覆盖同名内容或修改全局 MCP 配置。

## 连接、实例与现场

1. 优先使用现有 Blender MCP 工具；首次连接读取插件状态和场景信息。
2. 记录每个连接对应的 `bpy.data.filepath`，以及 `bpy.data.is_dirty`。端口、窗口名称和文件同名都不能单独证明目标正确。
3. 多个 Blender 实例可以使用不同端口。工具只暴露一组连接，不等于一个对话只能访问一个实例。先检查实际监听和工具能力，不要直接让用户换路径或重启全部应用。
4. 若现有工具不能选择端口，而本地插件确实提供该接口，可以使用 [scripts/blender_rpc.py](scripts/blender_rpc.py)。先 `inspect`；执行脚本时通过 `--expect-file` 校验目标。它不是越过权限或工具审批的替代通道。
5. 连接拒绝后，检查服务是否停止、端口是否变更。用户重新启动后再次读取文件路径，不沿用旧状态。
6. 从当前窗口的节点编辑器读取 `edit_tree`、选中节点和活动节点；区分节点名称、label 与其引用的 node group。需要视觉确认时获取界面或视口图像。

## 按任务选择流程

- 普通场景查询或编辑：先读相关对象、材质、修改器等状态，再实施最小必要变更，按可观察结果验证。
- 工程卡顿、切换可见性延迟或节点求值慢：读取 [references/project-performance.md](references/project-performance.md)。从具体触发动作和当前有效分支做对照，区分实测与推测；简报定位、依据、可能原因和优先操作，硬件与底层细节按追问展开。
- 创建或修改几何节点：按社区分流加载必要专题，并读取 [references/procedural-node-effects.md](references/procedural-node-effects.md) 中的高成本字段与烘焙输出要求；特别检查 Geometry Proximity 是否绕过 Bake 直通 Output Attributes。
- 既有节点参数失效、效果迁移、几何/材质解耦、面板简化或基础粒子改造：读取 [references/procedural-node-effects.md](references/procedural-node-effects.md)，结合控制链、采样空间、接口映射与可恢复的视觉基线处理。
- 节点组入库、跨工程追加、资产缩略图：读取 [references/asset-library.md](references/asset-library.md)。其中包括实例参数、依赖、分类、主文件合并、嵌入预览及磁盘验证。
- 同名资产更新、带控制器/材质驱动的系统同步：在入库参考基础上读取 [references/asset-sync.md](references/asset-sync.md)，先比较依赖与变更范围，保留库内布局，再验证实际联动。
- 复盘本次操作或理解这些约定的来源：读取 [references/2026-10-30-water-normal.md](references/2026-10-30-water-normal.md)。其中路径仅为历史案例，执行前必须重新确认。
- 复盘天空/涟漪/串珠/空气粒子的节点实践：读取 [references/2026-10-30-node-effects.md](references/2026-10-30-node-effects.md)。其中含参数回退、接口旧值与边界约束的反例，测试结果仅代表当时配置。
- 整理新的 Blender 经验、维护入口或评估是否拆分技能：读取 [references/skill-maintenance.md](references/skill-maintenance.md)。普通场景操作无需加载这份维护资料。

## 真实 Blender 中的实现约束

- 按节点类型寻找着色器，例如 `n.type == 'BSDF_PRINCIPLED'`，不要依赖可本地化的显示名称。
- 枚举值从 RNA 或当前运行状态发现；不同 Blender 版本的引擎、节点接口和 API 可能变化。
- 设置最终材质效果应修改着色器输入；`diffuse_color` 不能代替渲染材质。
- 对外部文件的读写、后台进程和用户偏好保存，遵守当前沙箱和审批规则。目标不在可写范围时，准备好操作脚本后申请对应权限。
- 后台辅助 Blender 使用 `--background --factory-startup --python-exit-code 1`，避免加载用户插件造成端口冲突和额外副作用。
- 需要副本时复制数据块。不要为了导出资产而改变源工程当前使用的节点组默认值或连接。
- 用户同时编辑其他对象时，首次确认后锁定本次目标身份；修改前重读目标模式与待改结构，避免当前选择变化切换操作对象。
- 多轮效果调参保留本轮前的材质、节点与实例参数快照；按用户所指版本恢复。结构/链接验证与视觉满意度分别说明，程序检查通过不能代替美术验收。

## 完成标准

按本次请求和实际执行阶段验证，不把资产入库要求套用于所有 Blender 任务。

- **通用交付**：说明查询结果或实际改动、验证依据、未完成部分和限制；涉及打开的工程时说明是否已保存。磁盘更新不代表现场窗口已经同步。
- **只读查询**：回答所问内容并说明相关现场依据；不为完成查询创建资产、保存工程或渲染。
- **场景编辑**：核对本次修改的对象、材质、节点、绑定或动画等结果，保留范围外的现场数据。只有实际修改几何时才做相关几何检查；只有要求持久化时才以磁盘保存结果作为交付依据。
- **文件、渲染或插件交付**：检查目标文件确实生成且内容可读取；图像检查实际效果，导出核对必要对象/依赖，插件验证本次功能。保存、渲染、安装和发布按各自授权执行，不因生成代码自动安装插件。
- **完整资产入库**：说明资产名、目标主文件、分类、缩略图与备份位置，展示已检查预览；验证数据内容、资产标记、分类及非空预览，并用独立后台进程读取保存文件验证持久化，详见资产入库参考。

用户只要求追加到另一个工程内存、只导出中间资产或暂不制作预览时，验证该阶段实际结果并说明保存/分类/预览中哪些未执行；不声称完整入库已完成。无法完成必要验证时如实交代，不以发出调用代替结果。
