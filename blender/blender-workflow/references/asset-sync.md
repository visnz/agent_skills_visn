# 既有资产同步：依赖、布局与联动

仅在更新库内同名节点组、材质或带控制器的系统资产时读取。通用新增、参数选择和缩略图方法沿用 [asset-library.md](asset-library.md)。这里的“同步”是本次显式更新，不建立自动双向同步，也不自动修改其他工程中已经 Append 的副本。

## 先确定替换范围

比较运行中的源和目标：节点类型、接口 identifier/类型/顺序、内部图和 driver；使用该组的材质/修改器；相关对象、约束、布局与资产元数据。源有未保存改造时，取当前内存数据。

| 比较结果 | 处理原则 |
| --- | --- |
| 独立节点组变化，实例无额外依赖 | 更新组并核对所有现有实例的接口映射和参数 |
| 驱动在材质节点树，读取另一个材质的参数 | 将必要材质一并更新，重连变量的 ID 与 data path |
| 库内已有功能一致的控制器、日月或其他对象 | 优先复用，重连依赖；不因节点变更重新导入整套对象 |
| 对象数据、约束或控制逻辑也发生变化 | 扩大到确有差异的依赖，明确保留与替换项；重大扩展先反馈 |
| 同名实际是不同资产，或接口重建后映射不明确 | 停止盲目替换，确定资产身份及映射；不按名称相似度猜测 |

不把旧组 `user_remap(new)` 作为完整迁移的充分条件。驱动可能位于组外，组输入数量变化也可能使 `inputs[index]` 字符串仍能解析，却指向错误参数。

## 依赖检查必须落到具体 owner

对更新范围内的 ID 及必要反向使用者检查：

- **节点与接口**：嵌套组、图像、材质、对象或集合引用，以及外部链接。参数按 identifier 对应；跨重建版本还要核对名称、类型和语义。
- **动画/驱动 owner**：对象、对象数据、材质、材质 node tree、独立 node group。记录每条 FCurve 的 data path、array index、表达式、变量类型及目标 ID。
- **目标路径**：SINGLE_PROP 等变量检查目标 data path；变换变量检查其对象/骨骼、通道和空间，不因无 data path 判断失效。只有 `frame` 表达式、没有变量的驱动也可能有效。
- **对象关系**：父级、约束目标、骨骼和变换空间，及引用这些对象的范围内使用者。
- **外部资源**：Library、图像和缓存的实际可用状态，分别核对路径与 packed 内容。

检查 driver `is_valid`、owner 路径和目标路径，还要检查解析后是不是正确 socket/ID。保留节点实例名或重建相应路径；不能假定 ID remap 会重写 data path 中的节点名和索引。

## 保留库内布局和资产身份

源工程的摆放用于构图，资产库可能已归零居中。除非任务包含布局迁移，保留目标对象身份、集合成员、位置、缩放和非驱动旋转，以及需要保留的父级/约束。

由新主控值驱动的转角和位置可以合理变化；不能一边要求昼夜联动，一边把受驱动通道锁死为同步前数值。检查静态布局和功能输出时分开处理。

更新既有数据时保留最终名称、已有资产标记、catalog、作者/许可等元数据和集合资产身份。需要完整控制链的用户应复用集合资产；单独拖出 shader group 不会自动带上组外材质实例的驱动和日月对象。

可采用如下受限更新方式，具体实现依版本与现场决定：

1. 在扫描目录外备份磁盘文件；目标有未保存改动时另存内存快照。
2. 向独立副本追加更新数据，用返回的 ID 建立明确的旧→新映射。名称请求列表和 Blender 填充返回 ID 的列表分开保存，避免把返回 ID 继续当名称键。
3. 如需 `user_remap`，先列清旧 ID 的实际使用者，确认影响均属于本次更新。材质重映射可以重连现有对象或驱动对材质的引用，但仍需逐项验证。
4. 对本次确认替换的旧 ID 完成引用转移、名称与元数据处理后再移除；不对全库执行 orphan purge，也不清理身份不明的 `.001`。
5. 核对目标布局、对象关系及预期数据变化。已有控制器可保留时，节点/材质更新不应增加整套重复对象。

若副本中的引用或接口不完整，先修正方案，不用正式主文件反复试错。用户后来明确改变参数来源时，以新要求修正待同步数据；源工程实例值与资产默认值不必相同。

## 联动验证：检查行为，不能只数驱动器

在独立进程/副本中选择有代表性的主控变化，观察下游结果。不要为测试任意系统固定写死同一组值。

| 系统 | 可观察验证 |
| --- | --- |
| 昼夜天空 | 改变主控昼夜值，检查天空输入、控制器转角、日月变换是否按表达式/约束联动 |
| 多材质共享色彩控制 | 改变色相/饱和度/明度，确认从正确主材质传到正确下游 socket |
| 几何节点/点云 | 同一输入、参数、帧和 FPS 下比较有效点/实例、坐标、半径或网格结果 |
| 组内时间驱动 | 在代表帧检查输出变化；单帧一致不代表完整循环正确 |

测试后恢复测试前值；验证进程不回写主文件。需要渲染时使用隔离场景，查看实际图像；需要更新缩略图时，将预览嵌入对应的现有资产 ID 后保存。测试场景、相机和演示材质不收进正式资产库。

正式保存后，再从磁盘打开目标重复必要的路径和联动检查，确认所有必要引用留在库内，未意外指向源工程或临时文件。对比接口、图结构、参数、资产元数据及缩略图，而不只报告节点/driver 数量。

检查数据清单时使用持久化基线：保存前的内存中可能有零用户临时节点组，重开后数量会不同。本次曾因此出现纯计数断言失败；与同步前已保存快照的 ID 名单及预期增删比较后验证通过。不要把所有数量差异解释成 orphan，也不要忽略缺失的实际资产。

## 交付与限制

说明更新了哪些 ID、保留了哪些布局/对象、哪些主控行为实际测试、是否保存与重读、备份位置和预览状态。区分本次静态同步与持续 Link 更新；其他工程中已追加的旧副本需要单独更新。

本流程在 Blender 5.2.3 LTS 的一次天空同步中验证过，另有多次节点提炼支持参数和预览做法；不声明覆盖任意 rig、模拟缓存、库覆盖或全部跨版本迁移。实践细节见 [2026-10-31-asset-extraction-sync.md](2026-10-31-asset-extraction-sync.md)。
