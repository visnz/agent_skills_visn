# Blender 工程性能分析

在工程卡顿、可见性切换等待、节点或修改器 evaluation 慢时读取。目标是定位用户实际遇到的延迟，给出有证据的原因范围与下一步。创建节点的输出设计另见 [节点效果工作流](procedural-node-effects.md)。

## 先确定触发动作，再检查当前有效状态

区分持续旋转视口掉帧、修改参数后等待、可见性开关求值、材质预览同步与渲染耗时。优先使用用户已给出的动作、计时和对照结果；缺少关键触发条件时才追问。

- 明确 Outliner 的眼睛、显示器和相机按钮，分别复现，不统称为“可见性”。眼睛对应视图层隐藏，显示器与相机对应对象级禁用；实际是否重算以该工程实测为准。
- 枚举 bpy.data 只能证明数据存在。核对对象所在集合、父集合排除状态、当前 ViewLayer、修改器视口/渲染开关、实际节点输出及缓存覆盖范围，再将其列为相关计算。被排除对象若仍被有效节点或实例引用，沿该引用继续核查。
- 用户持续操作时刷新与本次假设有关的状态。不要拿旧的渲染视口、Remesh 或插件注册状态解释新现场；也不凭状态差异揣测用户操作顺序。
- 区分应用修改器、几何节点 Bake、模拟缓存和属性写入；检查真正缓存的分支与下游消费者，不把“已烘焙”理解为全部输出停止计算。

## 用最小对照收敛原因

先读相关状态和引用链，选择能区分当前假设的一项对照；避免全场景统计后凭复杂度排名猜根因。用户已完成的对照可直接作为依据，注明来源，无新理由不重复昂贵测试。

- 在授权范围内对同一触发动作每次只改变一个因素，例如修改器启用、某一字段输出、缓存开关；记录前后耗时、帧、视图层和显示模式。交互等待、节点耗时与脚本更新时间不是同一指标。
- 涉及临时开关、断线或插件隔离时先保留状态，测试后恢复；性能定位不自动授权持久删节点、降精度或保存工程。必要时使用副本，避免重烘焙破坏有效缓存。
- 关闭整个修改器后变快，只能先定位到该修改器；继续检查内部节点、属性输出和绕过缓存的分支，不能直接宣称某个节点有 Blender 缺陷。
- 简单 Empty 或灯光开关慢时，检查被触发的下游求值；不要把触发对象当成计算大头。只有观察到相关依赖或计时证据时，再查驱动、插件回调或依赖图机制。
- 面数、节点数量、正常实例、Weighted Normal、插件已安装或 handler 数量都只能是线索。没有计时或隔离证据，不据此归因，也不汇报无关小对象清单。不建立“百万面以下一定不卡”的硬阈值。
- 同一文件跨机器有差异时先核对任务条件；用户已确认相同的变量不反复列检查表。硬件比较只在影响决策时简述，追问后再展开。

## 汇报与停止点

默认简报：问题位置与证据 → 大概原因（标记推测）→ 一两个优先动作。尚未定位就说明缺少哪项对照，不以长篇底层机制填补证据。不把弱嫌疑包装成“最强原因”。

用户给出反例时修正原结论，不继续围绕已排除因素展开。已达到用户可接受的速度后停止扩展检查。用户要求高精度或必要功能时，优先缓存结果、消除旁路输出与减少重复计算；不默认推荐低模代理、降采样或删掉必要节点。

## 案例：Proximity 属性输出绕过 Geometry Bake

2026-10-31，Blender 5.2.3 LTS 的湖面节点现场。该节点组此前由 AI 创建。以下为用户在同一工程操作中的对照反馈，非 Agent 独立计时或跨项目基准。

触发为灯光/Empty 的显示器或相机开关；眼睛按钮不触发同类刷新。关闭相关几何节点修改器后延迟消失。后续截图显示两条输出路径：

- Geometry 经属性写入、材质设置及 Bake 后进入 Group Output。
- Geometry Proximity 的 Distance 经 Map Range，直接进入 Group Output 的“涟漪遮罩（内部）”字段，连接到修改器 Output Attributes；这条字段路径没有经过 Bake。

| 用户对照条件 | 每次等待约 |
| --- | ---: |
| 不启用烘焙，保留属性输出 | 2.5 秒 |
| 启用烘焙，保留属性输出 | 0.5 秒 |
| 启用烘焙，关闭属性输出 | 0.01 秒 |

此前用户曾测到烘焙后约 0.7 秒；最新三组对照进一步将残余延迟定位到属性输出分支，不能继续解释为不可避免的场景整体开销。公司同文件也曾约 1.3 秒；这不构成节点缺陷或硬件异常的证明。

**得到的结论**：此工程的主要瓶颈是 Proximity 相关求值，且仅烘焙 Geometry 没有消除旁路属性输出的成本；关闭属性输出后本次触发延迟接近消失。后续创建此类节点要检查全部输出，避免在烘焙结构外继续输出未缓存的高成本字段。

**合理解释与边界**：字段输出绕过 Bake，与烘焙后仍存在额外求值相符；但是否复制了一份数据、是否重复构建空间索引，以及为何无关对象开关使其失效，均未做内部分析，不能写成已证实机制。关闭属性输出后的全部材质/渲染消费者是否保持预期仍需核对。保留必要高精度 Proximity，不把此案例泛化为禁止使用节点或所有属性输出。

本次 VRM 回调与静态面数的归因未获对照支持，且用户明确排除，不作为优化方案沉淀。新增的命名属性缓存方案也尚未在该现场重新实施验证，应按当前版本和消费者测试后采用。
