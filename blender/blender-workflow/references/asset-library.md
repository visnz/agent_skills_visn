# 节点组跨工程入库

适用于从当前选中节点提取可复用节点组，再合并到个人资产库主文件。普通场景查询无需加载本文件。

以下描述完整入库流程。用户若只要求检查、内存追加、中间导出或暂不制作预览，只执行对应阶段及必要依赖检查；明确哪些保存、分类、预览或注册步骤未执行，不将阶段性结果称为完整入库。

## 1. 确认源与目标

读取源工程路径和当前所选节点。若选中的是 `ShaderNodeGroup`，真正的数据是 `node.node_tree`；单个 Noise 等基础节点若需要封装为组，先按用户范围建立组和接口。

目标可能是三种不同的东西：

| 用户目标 | 实际需要完成的操作 |
| --- | --- |
| 另一个已打开工程 | 通过对应连接追加到它的内存数据；用户要求持久化时保存 |
| 指定资产库主 `.blend` | 将数据合并到这个文件，而非只在旁边另存一个文件 |
| 注册资产库目录 | 注册目录路径，让资产浏览器扫描其中的资产 `.blend` |

用户只给目录时，先列出目录中的 `.blend` 并读取现场路径。若能唯一确定，不反复要求用户提供已能查到的信息。同名 Downloads 副本与 D 盘正式文件必须通过绝对路径区分。

## 2. 核对实例参数与依赖

检查内部节点、嵌套组、图像、指定坐标对象、驱动和动画引用。若依赖其他对象，需要包含必要依赖或改造成可独立使用的接口，不可无声丢失。

对于节点实例输入：

- 比较实例 socket 值与组接口默认值，按 socket `identifier` 对应，避免重名接口混淆。
- 用户想保存当前调好的效果时，将实例值写入**导出副本**的接口默认值。
- 若实例输入有外部连接，`default_value` 不能代表连接产生的值；检查上游，按需要携带上游、暴露输入或询问如何处理。
- 保留接口范围、子类型、内部链接和节点参数。控制组重命名应在副本进行。

可用 `bpy.data.libraries.write(path, {group_copy}, fake_user=True, compress=True)` 输出最小中间 `.blend`，再用 `bpy.data.libraries.load(path, link=False)` 在目标追加。读取会携带 Blender 数据块依赖，但外部贴图文件的可移植性仍需单独核对。

源副本临时数据块用完后清理；不要删除仍被用户使用的数据。

## 3. 合并和分类

保存前读取目标 `filepath`、未保存状态与同名节点组。已有用户未保存改动或同名资产时，先确定可保留的处理方式；不要默默重载或替换。

保存主文件前创建一份明确命名的备份，优先放在资产库扫描目录外，防止备份中的资产重复出现。

追加后：

```python
group.use_fake_user = True
if group.asset_data is None:
    group.asset_mark()
group.asset_data.description = '说明效果、输入与输出用途'
# 从目标目录 blender_assets.cats.txt 读取现有 UUID，不能沿用其他库的 UUID。
group.asset_data.catalog_id = existing_catalog_uuid
```

保留用户目录结构；选择含义匹配的现有分类。无适用分类时再按需求新增 UUID 和目录项，不重写整个 catalog 文件。

注册目录和保存主文件是两个独立动作。确需注册时，先检查 `bpy.context.preferences.filepaths.asset_libraries` 是否已有同一路径；新增后用 `bpy.ops.wm.save_userpref()` 保存偏好。不要把“当前文件”列表中能看到资产误当成外部资产库已经注册。

## 4. 制作并嵌入缩略图

程序化法线节点可用平面或球体、简单反射材质及侧向软光展示细节。使用实际节点组和参数进行渲染，避免只截取节点连线作为效果预览。

用独立临时场景或后台 Blender 渲染，不污染源和目标中的相机、灯光与材质。使用运行版本实际支持的引擎和接口，适当降低样本和分辨率；例如 384×384 的预览通常足够用于 256×256 的资产缩略图。

打开渲染 PNG 进行视觉检查。若纹理看不清、全黑或反光淹没细节，调整光线与取景后重渲染。

嵌入到资产数据块：

```python
with bpy.context.temp_override(id=group):
    result = bpy.ops.ed.lib_id_load_custom_preview(filepath=preview_png)
assert 'FINISHED' in result
preview = group.preview_ensure()
assert preview.image_size[0] > 0 and len(preview.image_pixels_float) > 0
```

`asset_generate_preview()` 的可用性和效果取决于数据类型与运行环境；发出调用并不证明缩略图已产生。PNG 留在磁盘上也不等于已经嵌入资产。保存必须发生在预览载入之后。

## 5. 保存、验证与收尾

本节针对要求持久化到主文件的完整入库。仅内存追加时验证目标内存数据；未要求预览时不增加渲染和预览检查，并在交付中说明范围。

1. 在已核实的目标中执行保存，保留原文件身份。必要时在保存前再次校验路径。
2. 用独立后台 Blender 从磁盘打开主 `.blend`，读取资产组，验证 asset data、catalog UUID、内部节点、接口参数与非空预览像素。让验证脚本失败时返回非零退出码。
3. 对比本次导出的结构和参数，不用固定节点数量替代实际完整性检查。
4. 独立中间资产 `.blend` 若仍留在注册目录，可能和主文件中的资产重复显示。只对**本次创建且已确认身份**的中间文件移至扫描目录外，不删改用户原有文件。
5. 当前文件视图与注册目录视图可能缓存列表。必要时刷新或切换库，并核对实际可见结果；不要仅因缓存无结果反复追加。
6. 最终提供主文件链接、资产名、分类、预览图、保存与验证状态，以及备份位置。

## 常见问题

- **9875 连接拒绝**：先检查对应 Blender 的 MCP Server 是否启动，再尝试连接。不要因此断言多工程不受支持。
- **工具只有 9876**：可为客户端配置第二条 MCP 服务，或在权限允许下使用已核实的插件本地接口。永久配置修改应与用户意图一致，不是完成一次复制的前提。
- **重开工程后连到别处**：重新读取 `bpy.data.filepath`；服务端口与工程路径的绑定会随现场变化。
- **缩略图存在但重开消失**：检查它是否嵌入正确 ID，以及载入后是否保存，再从磁盘独立验证。
- **后台插件报错、端口冲突**：以 `--factory-startup` 启动辅助进程；不要为渲染而启动用户全部插件。
- **写操作超时或响应中断**：先重新读取目标状态，确认操作是否已经完成。不要自动重放追加、保存或移动文件脚本，以免重复资产或覆盖数据。
