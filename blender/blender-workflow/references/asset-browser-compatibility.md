# 多文件资产库与资产浏览器兼容性

在同一资产库放多个 `.blend`、批量收录图片，或分类目录出现却没有资产时读取。这里只处理 Blender 资产的表达、索引和显示诊断；上传到外部存储的具体操作不属于本参考。

## 先确定资产怎样被使用

- 资产库注册的是目录，目录内可有多个独立 `.blend`；根目录的 `blender_assets.cats.txt` 定义共享分类。现有清单生成命令若以整个根目录为参数，新增同级 `.blend` 通常无需修改调用它的 bat。先核对实际命令和扫描结果，不按文件名猜测。
- 批量导入前用当前 Blender 版本试一项：确认目标数据块能标记资产、重新打开后仍存在、清单中的 `id_type` 正确，**还要在资产浏览器中看到并按预期使用**。`asset_mark()` 成功、JSON 有记录、缩略图存在，分别都不能单独证明界面支持该类型。
- 若直接图像资产无法满足版本或使用方式，不要悄悄把“图片”改成交付物不同的材质或节点组。结合用户要拖到哪里，说明新资产的使用方式、输入输出和图片如何保留；用户意图不明时再确认。Matcap 着色器可选用节点组包装：内置已打包的 Image Texture 与 Matcap UV 映射，输出 Color/Alpha；这不是所有贴图的通用包装。
- 远程库的每个 `.blend` 应能独立使用：图片等外部依赖打包进文件，不跨 `.blend` 留链接。保存后在独立进程重开，检查每张图片的 packed 状态、资产引用和预览；需要严格保持原图时比较打包字节的哈希。

## “目录有、内容空”按层定位

1. **文件**：重开目标 `.blend`，确认资产数据块数量、类型、分类 UUID、实际依赖及非空预览。
2. **清单**：检查生成器扫描了哪些 `.blend`；在资产页 JSON 中核对 `id_type`、数量、`catalog_id` 和缩略图 URL 是否可定位到文件。分类出现只能证明分类被读取。
3. **同步缓存**：若使用远程库，比较当前缓存清单与本地生成清单的哈希及资产类型。仅本地生成成功不表示线上已更新；不要凭目录已出现推断资产页也已同步。
4. **现场界面**：用实际连接确认端口对应的 `bpy.data.filepath`、当前窗口/工作区是否打开 Asset Browser、选中的库与目录、搜索词、在线/离线及资产类型筛选。筛选关闭可能让受支持类型隐藏；打开筛选后仍为空时，回头核对版本支持和缓存，不把筛选当作唯一原因。只有实际看到资产和完成一次预期用法，才称界面验证通过。

## 2026-11-20 Matcap 案例与边界

在 Blender 5.3.0 的一次批量入库中，641 张 512×512 PNG 作为 `Image` 数据块标记资产并打包；独立重开、原图哈希、清单中的 641 条 `IMAGE` 和缩略图均通过检查。远程缓存也收到这些条目，但用户看到 Matcap 分类为空。一次现场检查发现图像筛选关闭；改动筛选后用户仍报告为空，随后连接到的是已重开的另一个界面，未获得同一窗口的可视前后对照。因此不能把单次筛选状态断言为根因。Blender 5.3 [官方资产类型列表](https://docs.blender.org/manual/en/5.3/files/asset_libraries/introduction.html#supported-assets)未列出独立 Image，这提示应先验证版本兼容性，而不凭清单成功推断可显示。

后来将同一批打包图片各自封装为 `ShaderNodeTree`：每组引用一个本地 Image、同文件内的 Matcap UV 组，并输出 Color/Alpha。独立重开确认 641 个节点组、641 张图片、原打包字节不变和无外部库链接；重新生成的清单有 641 条 `NODETREE` 与对应缩略图。**当时仅验证了本地文件和本地生成清单，未记录新版本上传后在远程资产浏览器中的可视复验**。后续遇到相同症状，应以当前 Blender 版本和实际界面再做单项试用，不把这次包装方案推广到所有图片资产。
