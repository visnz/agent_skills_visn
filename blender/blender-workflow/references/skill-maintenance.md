# Blender 经验归档与技能拆分

只在复盘、更新 Blender 技能或评估拆分时读取。普通操作不加载本文件。建设方法遵循仓库的 [技能建设规范](../../../docs/skill-building.md)，目前保留一个 `blender-workflow` 入口，不预建空专题或多个 Skill。

## 新经验如何归位

| 经验类型 | 归档位置与条件 |
| --- | --- |
| 跨多类 Blender 任务的个人决策 | SKILL.md；如读取当前选择、确认工程身份、保留用户参数和授权范围 |
| 特定交付的个人流程 | references/ 中对应工作流；如入库、渲染交付或跨工程迁移，有实际内容再建文件 |
| 单次操作的现场与证据 | 对应案例；说明版本、目标、已观察结果、未确认原因，路径和参数不作为默认配置 |
| 重复且容易出错的确定性操作 | scripts/；用参数或现场发现代替硬编码，说明依赖、副作用并验证 |
| 社区已覆盖的通用方法 | 优先复用现有专题分流，不复制一套社区教程；只有个人差异、集成约束和实测限制值得另写 |
| 暂无复用用途或证据不足的现象 | 留在对话或有价值的案例中，标记待验证；可以无需修改 |

先查已有工作流和案例，能更新则不重复新增。入口只保留选择条件、共享约束、完成标准和读取时机；新参考必须有按需入口。不要求每类任务都写案例，也不为一次参数调整单建文档。

参考资料开始难以查找时，再按已形成的工作流分组或补简短索引；不按未来可能用到的全部 Blender 功能预建目录。现有资产入库流程和水波案例继续保留，社区来源/分流与个人经验各自维护。

## 何时评估拆成独立 Skill

拆分应解决实际发现或执行问题。综合判断：

- 已形成可独立描述的用户请求、触发条件和交付物，其他任务很少需要其细节。
- 工作流、资源和验证方式已有实践依据，作为独立入口能更准确发现并减少无关装载。
- 单入口已出现真实问题，例如描述过宽、分支互相干扰、反复加载无关内容；仅拆参考资料仍不足以解决。
- 独立后的共享规则和依赖可以清楚维护，不会复制大量连接、授权和现场保留规则，或产生互相强制调用的循环。

这些是判断依据，不是必须凑齐的固定数量，也不以文件数、篇幅或社区专题数量自动触发拆分。例如资产维护若积累多种稳定且常被独立调用的操作，可评估独立入口；一次灯光调整经验通常补参考即可。

实际拆分前先给出候选边界、预期收益、共享规则和迁移影响，让用户决定；本次维护授权不扩展为未来任意拆分。获准后保留必要引用，更新索引、安装关联与调用边界的说明，避免旧入口失效；仓库外安装或配置按授权执行。

## 验证与收尾

经验记录说明实际验证到哪一阶段。历史社区测试不证明新的个人工作流、所有版本或美术质量；维护文档不要求运行全部社区测试或重做 Blender 场景。

较完整、较大的实践任务收尾时，若有新经验，可提示一次是否按 README 整理；已明确要求整理时直接执行，不重复询问。按仓库规范说明沉淀位置、验证范围及暂未纳入的原因。
