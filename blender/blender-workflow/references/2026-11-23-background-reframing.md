# 远景重构图：空间压缩反例与 50% 候选

记录日期：2026-11-23。状态为**局部有效、视觉未完全达标、按用户范围停止修改**。个人判断流程见[白盒与静态帧构图](whitebox-blockout.md)。这里记录既有建筑布局调整，不是白盒生成或建筑测量任务。

## 输入与已运行尝试

现场为 Blender 5.3，通过本地 MCP 操作。用户提供新的构图、上一版图像及旧工程，要求保留前景门框、人物、树、栏杆与当前相机，只调整远景建筑，并保持世界 Z 不变。

检查发现远景原位置没有变化，而两版相机的焦距、高度和移轴不同。实际先用包围盒投影，再用求值屋顶/檐口顶点采样，计算各建筑的 X/Y 平移，使远景在新相机中的大小及位置接近旧图。局部墙片随所属建筑平移，角部构件曾使用相邻位移的平均值；这不证明各连接已经吻合，不能固化为附件处理规则。

程序检查支持目标对象的 Z、旋转与缩放没有改变，非目标对象世界矩阵、主相机、帧号和选择保持。查看了两轮主相机预览。历史现场记录包括 `current_layout.json`、`reference_layout.json`、`layout_plan_v2.json`、`final_verification.json` 与 `attempt_02.png`；这些只作为本次已有记录的文件名线索，未随技能仓库收存，之后需要重新确认来源与内容，不把它们当作可直接使用的配置或已独立复验的附件。

## 用户反馈与证据边界

用户提醒建筑之间尽量不重叠，除非有意营造压缩空间或服务当前角度；一般最多轻微交叠。调整后的版本整体压缩感很强，而且下方地面/“地平线”在画面中的关系改变，导致参考图的感觉没有被还原。数值投影趋近和局部视觉改善并不代表完整构图验收通过。

本次没有完成逐对建筑实体穿插检测，也未将该地面线严格识别为真实透视地平线或可见地面边界。因此，不记录为“零重叠”“空间通过”或“地平线机制已证实”。可确认的反例是：只追建筑的投影大小和位置，容易忽视保护前景后的地面关系、院落留白与建筑排间纵深。

用户明确不需要继续修改，只要求总结经验；场景因此保持最后一版。旧版局部检查仍有效，但不应以它们替代本轮用户的美术评价。

## 50%：值得尝试，尚未运行

用户进一步说明，参考图通常可能是希望获得类似的感觉，而不是完全一比一还原位置；本次可把原布局与过于压缩的强匹配布局之间的线性中点视为一个方向。随后明确：**不是每次这样做都会更贴近感觉，50% 只应记为“值得尝试”。**
