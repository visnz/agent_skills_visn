# 微信聊天记录导出

把电脑版微信（4.x 新数据库格式）里的聊天记录解密导出，按需产出两类交付物。两条分支共享「定位数据 → 解密数据库」底座，之后分流：

- **HTML 归档**：全量还原聊天记录（文字、图片、语音、文件、自定义表情）为可离线浏览的 HTML，适合备份、留档、清理手机空间。
- **语料**：导出目标单聊并清洗成 A/B 对话切片，适合训练、风格提炼。

全程本地运行、不联网上传数据。这是综合性特殊任务（横跨逆向解密、SQLite 读取、媒体转码、数据清洗），不属于日常文本处理。

## 什么时候用

- 用户想"导出微信聊天记录""备份和某人的聊天""把聊天整理成可浏览的存档""导出成 HTML 离线看"。
- 用户要"提炼某人的说话风格""训练模型模仿某人的语气"。
- 用户明确说"解析微信数据库""导出聊天记录成 CSV/Excel/语料/HTML"。

不适用：只要"手动复制几段话"的轻量需求；用户要的是官方备份（那是加密的 `.bak`，不是明文）。

## 核心认知（先跟用户对齐）

1. **微信官方不提供明文导出**。所有导出要么是加密备份，要么靠第三方解析本地数据库。
2. **微信 4.x 换了数据库格式**（不再是 3.x 的 `EnMicroMsg.db`）。消息库是 `db_storage/message/message_*.db`，SQLCipher 加密，密钥需从运行中的微信进程内存抓取。
3. **两条分支的目标不同**：归档要「全量还原、可浏览」；语料要「结构化对话配对」。开工前先问清要哪个，或两个都要。
4. **角色映射要先定**：涉及多账号（大号/小号）或群聊时，"我"和"对方"是哪些 wxid，直接决定身份判断和左右气泡。

## 共享底座：定位 + 解密

两条分支都先做这两步，细节见 [references/wechat-4x-decrypt.md](references/wechat-4x-decrypt.md)：

1. **定位数据目录**：默认 `Documents\xwechat_files\`（4.x），微信内 `设置 → 文件管理 → 文件保存位置` 最快。
2. **解密**：用开源工具（wechat-decrypt 等）抓密钥 + 解密 `db_storage/` 下各库，**必须保持微信登录在线**；抓密钥需关一次微信重开。

## 分支一：HTML 归档

全量导出为可离线浏览的 HTML。完整流程、关键破解（图片 V2 加密、wxgf 容器、语音 SILK、自定义表情 CBC）和脚本用法见 [references/archive-export.md](references/archive-export.md)。

流水线（脚本在 `scripts/`，`archive_` 前缀）：

```text
archive_export_all.py          # 抽取消息 → messages_raw.json
archive_process_media.py       # 媒体分阶段：emoji_map / voice_index / images / files
archive_process_voice.py       # 语音 silk→mp3（独立 voice_env 跑）
archive_process_emoji.py       # 自定义表情 CBC 解密→转码
archive_preprocess.py          # 分组去重 → merged_by_month.json + chat_by_month.json
archive_gen_html.py            # 生成 HTML（index + merged + 单聊）
```

关键决策点：

- **账号/身份**：导出几个账号、谁是我谁是对方，改各脚本顶部的 `ACCOUNTS` / `SENDER_MAP` / `MY_WXIDS` 配置块（见 archive-export.md 的「账号配置」表）。
- **媒体范围**：图片/语音/表情是重活，量大时后台跑；"点到为止"指自定义表情只解密本地收藏的、不联网补全。
- **群聊**：两个账号各有镜像，用 `server_id` 去重合并进时间线，标注来源。

## 分支二：语料

导出目标单聊并清洗成 A/B 对话切片。见现有流程：

1. 从 `contact.db` 核对目标联系人（username/remark/nick_name/alias，用户称呼可能对不上）。
2. 按 wxid 导出成 TXT（格式 `[时间] [说话人] 内容`），需要 `zstandard` 依赖。
3. 用 [scripts/clean_corpus.py](scripts/clean_corpus.py) 清洗成切片、场景分类、隐私提示。

清洗脚本用法：

```text
python scripts/clean_corpus.py 输入.txt --a "输入角色显示名" --b "目标角色显示名" --out 输出目录 --prefix chat --gap-minutes 30
python -B tests/test_clean_corpus.py
```

清洗细节（过滤、多行续行、身份校验、间隔切片、场景分类、隐私提示）见原 SKILL.md 历史记录，核心规则：

- 过滤非文字消息（Sticker/Image/Video/Audio/File/转账/系统提示），剥离引用和图片 XML 噪声。
- A/B 必须不同且与输入身份一致；未知说话人、损坏头、倒序时间会报错，不自动归入 B。只支持已核对的双人会话。
- 默认 30 分钟间隔切分会话，连续同角色合并成轮，生成 A→B 候选对。
- 分类和配对需抽样核对；隐私检测只提示、不自动删。

## 关键决策点（需要问用户的）

1. **要哪个分支**：HTML 归档 / 语料 / 两个都要。
2. **角色映射**：谁是"我"、谁是"对方"（多账号/群聊时尤其重要）。
3. **隐私处理**：归档默认全量本地保存不外传；语料的隐私检测只提示、不擅自删。

## 完成标准

- 数据目录已定位，消息库已解密（验证明文可读：能列出 `Msg_*` 表）。
- **归档分支**：HTML 生成完整（index + 合并时间线 + 各单聊），媒体（图片/语音/文件/表情）转码完成且路径正确、文件存在；报告消息数、媒体各类数量、覆盖率和缺失项。
- **语料分支**：产出切片、场景分类、隐私提示三份文件，报告消息/过滤/续行/轮次/配对/未配对/隐私提示数量；已有输出不覆盖，解析错误返回非零。
- 全程不把解密明文、密钥、聊天对象身份外传。

## 约束与边界

- 解密工具从官方仓库下载，不用不明来源安装包。
- 抓密钥、解密涉及隐私，动手前说明"会关微信重开""全程本地"，征得同意。
- 脚本不硬编码真实人名/微信号，用参数或配置传入；交付文档不出现真实聊天对象身份。
- 临时工作目录任务完成后按用户要求标记可删除，不擅自清理用户数据。

## 验证情况

- 解密 + 语料分支：此前任务已用虚构样例验证清洗脚本的身份校验、多行保留、间隔与过滤断点、倒序/损坏输入、防覆盖等（见原记录）。
- 归档分支：本次实战完成过一次全量导出（29.4 万条消息、71 个月、34GB 媒体），图片/语音/表情三类媒体解密转码链路均验证有效，HTML 离线可浏览、媒体路径正确。账号参数化（导出他人资料）尚未在实际第二次导出中验证。
