# 既有聊天归档的持续维护

用于已有用户标注、多个来源或定制阅读器的归档。先核对实际代码与当前状态；初版导出脚本不等于现场最新版。

## 维护前的基线

- 读取现场交接、生成器、交互脚本、服务和相应数据清单。文档过时或与实际文件冲突时，重新核对证据，不用旧描述覆盖新代码。
- 分开记录原消息数量／内容／顺序、消息锚点、用户状态，以及新增来源数量。数据文件里的数组顺序不一定等于页面显示顺序。
- 保留 bookmarks.json（书签、备注、进度）、annotations.json（独立批注）、deletions.json（软删除）。独立批注为空不能推断书签备注丢失。
- 变更前后核对相关内容或 SHA-256；用户同时标注时重新读最新状态，不回灌维护开始时的快照。只因哈希变化就覆盖回旧文件会丢失用户新操作。
- 不默认创建整目录备份；有必要时按用户要求使用最小备份或已有版本记录，不擅自清理其他任务的产物。

## 媒体关联与稳定锚点

- 对图片身份，优先使用账号＋消息原生 ID／server_id＋资源索引。文件大小、时间相近或宽高比仅能用于排查，不能作为确认关联的证据。
- 某次 Windows 微信 4.x 修复通过 packed_info_data 的嵌套字段取得本地资源 ID，再定位 attach 下原图／高清／缩略版本；字段位置必须按实际版本和样本验证，不当作所有微信版本的固定协议。
- 区分资源 ID 与图片内容 MD5。纠正误用的字段时，保留旧 archive_id；生成器优先使用已存在的稳定标识，避免旧书签与引用失效。
- 对已经确认身份的候选实际解码，完整版本优先，比较像素面积后选清晰可读者。缩略图可能裁切，比例差异不能推翻原生关联证据。
- 清单保存消息锚点、原生关联依据、输入／输出路径、格式、尺寸、摘要及质量等级；转码后的字节哈希不同不代表身份错误。不要将生成的内容摘要文件名再猜映射到旧目录。
- 修复图片时同步合并与单聊数据，并核对输出 SHA-256、可解码性和 HTML 引用。缺失关联就明确停止或标待补，不静默退回猜配。
- 只有验证了相关媒体类别，才报告其覆盖情况。图片修复不能代表语音、视频或表情也已补全。

## 书签与保存确认

按这个阅读器已约定的四种语义维护；新项目先确认自己的语义，不把本案例颜色强加给其他用户：

| 类型 | 含义 | 排序／数量 |
| --- | --- | --- |
| red | 阅读进度 | 全局一个，设置新进度替换旧进度 |
| yellow | 待选／笔记 | 多个，可留空备注、编辑、删除、跳转 |
| green | 时间线序号 | 按原聊天时间从早到晚连续编号；补标旧消息后自动顺延 |
| blue | 回复 | 复制黄色交互，独立多选清单，不参与绿色编号 |

- 保留 id、mid、note、t、created；t 是原消息时间，created 是添加标签时间。绿色不同聊天时间的主排序不得使用 created。同秒需要明确稳定的原消息次序；不要把当前实现的添加时间兜底宣传为完全匹配同秒消息顺序。
- 新增类型同时处理默认状态、旧数据归一化、保存载荷、总数、消息挂签、菜单、独立分组、颜色与空备注提示。旧文件缺少 blue 时读作空数组，不先重写用户文件。
- 旧书签通过 mid 查原文，跨月根据 t 加载相应合并页面；同一月份复用读取。用文本节点或转义展示原文与备注；媒体预览限制为可信本地／同源路径。
- 首次状态读取失败时阻止编辑，保留重试入口；不能用空数组覆盖真实书签。POST 成功后再 GET 回读相同内容，确认后才显示已保存。
- 同一页面的同类保存排队，连续编辑保留最新载荷；失败保留待保存内容，离开页面前提示。只读打开面板不得触发保存。
- 排队与回读仅验证本页保存链路，不能证明多标签或多设备的整文件覆盖写入安全。跨端使用前核对是否有版本检查／冲突处理；未实现时不要宣称具备并发合并能力。
- HTTP 模式通过服务 API 保存硬盘 JSON；file:// 模式用浏览器 localStorage。两种来源的状态不自动互通，离线状态行为须在目标浏览器验证。

## 全局关键词搜索

- 从规范化的合并消息生成独立本地索引，至少保留稳定消息 ID、月份、时间、来源、发送人及已有文本。不把书签备注误作原聊天，也不声称识别了图片／语音内容。
- 搜索范围与统计范围分别定义。本案例仅搜索微信／Telegram 已有文本；微博／小红书混排不自动加入聊天搜索。
- 以普通包含匹配支持中文、英文不区分大小写。字面关键词不当作未转义正则或 HTML；正文、摘要、关键词及链接参数分别转义／编码。
- 提供来源、发送人、时间排序和可选包含软隐藏消息；默认排除已隐藏项。大量命中分批显示，输入防抖并处理中文输入法组合事件。
- 点击结果进入合并月份的稳定锚点，高亮目标文字并保留前后聊天；返回结果保留关键词和筛选。明确包含隐藏项时可临时显示该条，不修改删除标记。
- 如果要支持 file://，可把索引写成同目录静态 JS，避免依赖 fetch 本地 JSON；索引仍包含私密聊天，不上传到外部搜索服务。
- 将索引与搜索页接入日常重建，而不是只手工生成一次。空关键词、零命中、加载失败分别给出可见状态。

## 缓存与实际页面验证

出现“新页面已显示、输入不回填、状态栏空白、工具栏缺新按钮”时，先区分页面／索引／交互脚本是否来自同一版本。

1. 查看用户实际 URL、筛选和页面状态；必要时只读检查脚本 URL、索引条数与新功能标记。
2. 比较磁盘／服务提供的新脚本与浏览器加载结果。索引存在不代表搜索代码已经启动；新测试浏览器能用也不代表用户原 Chrome 没有旧缓存。
3. 给共享 JS、CSS、索引加内容相关版本参数，并同步首页、所有层级页面和生成器。生成器自身产生资源变化时，也要使版本随之变化。
4. 在用户实际页面刷新并复测原关键词；有未保存操作时先处理保存状态。只改静态文件通常不需要重启服务。

按需要验证搜索、结果跳转、高亮、返回筛选与控制台错误；不只检查字符串是否出现在源码中。缓存案例见 [阅读器扩展案例](2026-11-reader-extension-case.md)。

## 服务与局域网

- 区分静态页面变化和运行中 Python 服务变化。监听地址改动后需要重启；源码里出现新地址不能证明当前进程已经监听它。
- 本机阅读用 127.0.0.1；用户明确授权同网访问后才扩大监听范围。0.0.0.0 是监听地址，访问使用本机实际局域网 IP，并检查防火墙条件，不硬编码案例 IP／端口为永久配置。
- 开放前说明已有服务是否无认证，以及能连接者能否读取聊天、操作书签／批注。不要未经授权改路由映射、开放公网或关闭安全保护。
- 历史服务把项目目录作为静态根来解析 html 与 media。接管时检查真实可访问范围和路径约束，不因页面链接未列出就认定源 JSON／项目文件不可下载。
- 进程控制不可用时完成源码变更，但把“待重启”“未测局域网／防火墙”单列；给出确切启动入口。不要借另一应用或替代进程通道绕过被拒绝的执行权限。

## 最小回归与交接

- 阅读器变更：原消息／锚点／标注保留，新旧数据兼容，实际交互有效；书签增加颜色时不改其他颜色语义。
- 搜索变更：已知存在／不存在的关键词、标点／HTML 文本、来源与发送人、分批显示、锚点跳转；所有索引 ID 可在目标 HTML 找到。
- 来源变更：合并幂等，原聊天内容和顺序未变，独立来源在重建后仍在；来源开关不会改变聊天统计。
- 媒体变更：关联、摘要、可解码、引用路径及待补数量；不为验证功能向用户正在标注的真实状态写入临时测试项。
- 只声明实际运行的验证。不能执行测试时可做结构／差异检查并说明限制，不借用旧测试结果冒充本轮通过。
- 交接分别列源码／运行／浏览器状态与未完成事项。保存报告不等于工作仍在后台进行；恢复旧任务前重新读取状态。
