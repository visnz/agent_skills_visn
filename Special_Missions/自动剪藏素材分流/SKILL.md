# 自动剪藏素材分流

把「剪藏 → 手动搬运」的琐碎活，做成一个**双击就跑完的本地脚本**：自动读剪藏链接、下载视频/图片、入库素材库、确认成功后再删源词条。这是综合性特殊任务（横跨 Wolai/Eagle 的 MCP 接口、网页抓取下载引擎、去重与防误删），不属于单一领域技能。

## 什么时候用

- 用户说"我要省去每天回家一个个打开链接、猫抓下载、手动拖进 Eagle 的麻烦"。
- 用户想"把剪藏的内容自动分流"（按来源类型分别处理）。
- 用户要"写一个本地脚本，需要整理时跑一下"，而不是 7×24 实时同步。

不适用：只要"手动复制几张图"的轻量需求；用户要的是实时后台监听（那是服务器常驻方案，见「架构决策」）。

## 核心认知（先跟用户对齐，再动手）

1. **先确认两端是否开放接口，这决定方案能不能成。** 不要凭旧印象下结论——例如"个人版 Wolai 没 API"是过时信息，实际上 Wolai 已开放官方 MCP（`https://api.wolai.com/v1/mcp`），个人版就能读页面、删块；Eagle 有本地 MCP（`127.0.0.1:41596/mcp`），支持直接 `item_add` 入库并打标签。先实测接口（`tools/list`、读一个真实页面），别急着设计。
2. **架构选本地脚本还是服务器，取决于用户真实节奏。** 用户说"不用实时同步，回家跑一下就行"时，立刻砍掉服务器常驻、同步盘、SSH 中转——整个方案缩成一个本地 Python 脚本 + 双击 bat，零服务器、零常驻、零同步盘。
3. **"下载引擎"基本都有现成轮子，别自己写。** 小红书用 XHS-Downloader（支持 CLI，可被脚本子进程调用）；X/推特用 gallery-dl。先确认这些轮子的真实调用接口（CLI 参数、导入路径），再对接。
4. **账号风险要主动提示并给免登录替代。** 抓取类工具配 Cookie（auth_token 等）能提画质/成功率，但有封号风险。用户珍惜账号时，明确区分"登录态抓取（有风险）"和"免登录公开接口（零账号风险）"，优先后者；免登录接口在部分网络下可能不稳（如国内访问 Twitter CDN），如实说明并给重试/镜像方案。

## 架构与流程

标准闭环（本地脚本）：

```text
读剪藏页面（Wolai MCP get_page_blocks，一次性拿整页扁平块列表）
  → 识别链接类型（小红书/xhs、X/twitter、图片 image 块）
  → 调用下载引擎下载到独立临时目录（每个作品一个目录，避免残留）
  → 入库 Eagle（item_add，打标签 + annotation 存来源）
  → 解析返回的 successCount，确认真的入库成功
  → 删除 Wolai 里对应的词条块（delete_block）
```

关键设计：**入库成功 → 确认 → 删源**，删源严格依赖确认成功，防止误删。详细接口、字段结构、参数见 [references/platform-apis.md](references/platform-apis.md)。

## 真实踩坑（通用性强，跨项目有效）

1. **多 Python 环境导致依赖错位**：Windows 上 `python`、`py`、IDE 内置解释器可能各指向不同 Python。装依赖时装到了 A，双击 bat 时命中 B（缺依赖）。**修复**：bat 里写死验证过的那台解释器的绝对路径，让双击和依赖永远对得上。
2. **下载器内部去重与脚本去重冲突**：XHS-Downloader 有内置去重库（记录作品 ID，下载过就"跳过"），会让脚本拿到空产出。**修复**：用脚本自己的 `state.json` 做唯一去重，给下载器加 `--download_record false` 关闭内置去重。
3. **MCP 返回含中文导致 JSON 解析失败**：Eagle 的 `item_add` 传中文 `name` 字段时，服务端返回把 UTF-8 中文错误解码，导致返回 JSON 损坏、`json.loads` 失败。**修复**：不传中文 `name`，中文信息改存 `annotation`（注释字段对中文安全）。
4. **SSE 的 data 可能多行**：MCP 返回是 SSE 格式，`data:` 后可能跨多行，只取第一行就 `json.loads` 会失败。**修复**：把连续的 `data:` 行拼接后再解析。
5. **bat 中文乱码**：Windows 的 cmd 默认用 GBK 读 bat，UTF-8 中文会乱码、被当命令执行。**修复**：bat 用纯 ASCII，或 `chcp 65001` 后仍避免中文。

## 需要问用户的关键决策

1. **要处理哪些来源/平台**（小红书？X？图片？B 站？），分别打什么标签。
2. **本地跑 vs 服务器常驻**——用户说"回家跑一下"就选本地脚本。
3. **是否接受配 Cookie**——涉及账号风险，用户珍惜账号时走免登录方案。

## 完成标准

- 脚本能双击/一条命令跑完，且用验证过的解释器路径运行。
- 端到端实测通过：至少一条真实链接完成「下载 → 入库 → 确认 successCount → 删源词条」。
- 去重、防误删逻辑正确（Eagle 返回失败时不删源，下次重试）。
- 脚本不硬编码 token/密钥，用 config 或环境变量，交付文档不出现真实凭证。

## 约束与边界

- 敏感信息（Wolai token、页面 ID、Cookie）不写进技能或交付文档，用占位符。
- 涉及账号登录态的抓取，动手前说明风险并征得同意；优先免登录公开接口。
- 脚本不硬编码真实路径/身份，用参数或配置传入。

## 验证情况

- 本次实战完整跑通：小红书链接（视频 + 图文 50 张）下载入库 Eagle + 删 Wolai 词条，全程端到端验证有效（见 [references/2026-10-31-xhs-sync-case.md](references/2026-10-31-xhs-sync-case.md)）。
- X/推特分支：代码已写好（gallery-dl），但因用户珍惜账号、未配 auth_token，**未实际验证下载**，仅验证了链接识别。
- 免登录 syndication 接口：验证了算法与偶发可通，但在用户网络下 SSL 不稳，未作为可靠方案采用。
