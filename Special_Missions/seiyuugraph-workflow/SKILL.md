# SeiyuuGraph 项目维护

这是从实际开发、反馈修复、迁移和首次 Git 提交中提炼的项目专用入口。与微信导出等特殊任务同级，围绕本项目长期维护，不为每项新功能再拆技能。

## 接手时先做

1. 确认用户要审查、修改、补齐、发布还是清理；审查保持只读，整理技能本身不触发抓取、停服或发布。
2. 找到实际项目目录，先读其中的 `AGENTS.md`、`README.md`、`docs/HANDOFF.md`，再按问题读项目上下文或数据模型。历史名称为 `SeiyuuGraph`，后迁移到 `seiyuu_sites`；运行目录、数据路径和当前 Git 状态须现场核对。
3. 区分正式目录、旧入口、隔离开发副本和发行包。图里少了对象时，先查访问的服务、数据目录和筛选，不先用旧快照覆盖当前库。
4. 按下表只加载本次需要的资料。早期报告、项目文档和测试数量都是证据线索，实际代码/输入与本轮验证决定结论。

## 修改中要保留的项目语义

- **选择、喜好、关注、忽略独立。** 星级不自动变成图种子；重点关注只强调显示；忽略要从图计算与证据中排除，不删除收藏或原资料。
- **出演按作品保留证据。** 使用 `(作品ID, 角色ID, 声优ID)`，不按声优数组顺序推定主CV，不把人物地区当作具体作品配音语言。
- **阈值数不同所选对象。** 同一所选声优在一作品多个角色只计一次；所选角色只算本人出演；作品对象本身不计人数。筛选后保留必要证据，再考虑节点上限。
- **查过就保存，手动加入优先。** 完整一级关系复用本地；无独立中文名、无生日等负结果也保存；错误退避可重试。优先任务不递归展开所有新对象。
- **浏览动作有边界。** 单击选择、双击开详情，批量操作直接使用选中ID；保持手调节点、分组、缩放与弹窗背景滚动。异步旧响应不能覆盖新选择。
- **保留私人数据。** 当前收藏、角色/声优星级、备注、手工名、永久忽略和关注均需保留。测试和朋友空库不写回真实目录。

## 选择相称的验证

先挑能反驳当前修复的例子：分页中断、同角色多声优、跨作品同CV、同ID不同实体桶、阈值提高却结果变多、较早请求较晚返回等。再按影响运行相应模块的检查。

项目常用命令，在确认后的项目根目录执行：

```powershell
python -X utf8 -B -m unittest discover -s tests -p "test_*.py"
node --test tests/*.js
```

不要仅为回顾经验重跑整库抓取或整个业务。测试使用临时目录；依赖个人历史快照的检查明确可选，不为通过测试把私有夹具带进源码包。

图手势、滚轮、弹窗跳顶、节点吸附和中文标签可读性需要实际页面输入验证；静态断言或截图存在只支持相应层级。数据迁移、进程重启、静态发行和 OSS 上线分别说明验证到哪一层。

## 完成时交代

- 解释改动解决了哪个可观察问题、采取了什么数据/交互口径、如何验证及仍有哪些限制。
- 交接文档指向当前仍存在的路径；运行数量、PID、端口、测试计数标明观察日期，不作为长期固定预期。
- Git 提交、推送、OSS 上传、技能安装各自按本次授权和实际结果说明。技能文件写入仓库不等于已经安装或自动供所有助手使用。

## 适用边界

现有方案是 Python 标准库本地服务、原生网页、SQLite + JSON；静态版只查看已导出信息。多人云端写入、鉴权、跨设备浏览器工作区同步和完整游戏语言版本建模，需要独立设计及验收，不能从“可以部署 OSS”推导为已具备这些能力。
