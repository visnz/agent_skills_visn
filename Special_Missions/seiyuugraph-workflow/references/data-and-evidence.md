# 数据模型与可追溯关系

用于导入、名称、出演、CP、地区、图阈值和生日问题。先核对项目内 `docs/DATA_MODEL.md` 和对应实现；以下保留本项目踩过的语义边界，不是对线上 API 当前版本的保证。若要修改接口契约，另外核对官方文档与实际响应。

## 1. 分开收藏状态、作品类型与评分

| 维度 | 项目使用的字段/口径 | 常见错误 |
| --- | --- | --- |
| 作品类型 | `subject_type`，动画/游戏分别查 | 与收藏状态 `type` 混用，导致搁置/抛弃数量错误 |
| 收藏状态 | 1想看、2看过、3在看、4搁置、5抛弃 | UI支持五种，后台仍只合并旧三种 |
| 个人评分 | 收藏的 `rate` | 与社区评分混合筛选或入队 |
| Bangumi评分 | 作品的 `score` | 把“≥7.5分作品”解释成用户给分 |
| 角色定位 | 某作品中的主角/配角/客串等 | 一个全局角色定位覆盖所有作品 |

导入先按用户选择的“作品类型 × 收藏状态”完整分页，按ID去重并检查预期数量；所有页成功后再替换本次同步范围。中途超时、重复页、数量异常或账号不匹配时保留旧快照。未选择的类型/状态保留；独立星级、备注和手工名不跟着导入重置。

验收用虚构分页数据覆盖：跨页、状态流转、作品移除、局部同步、重复ID、失败、另一个账号。历史真实作品数不能硬编码为长期验收数量。源代码中的旧注释也可能过时，要与实际参数和用例对照。

## 2. 实体身份、名字和完整度

- 身份使用 `(kind, id)`，`character:100` 与 `person:100` 是两个对象；JSON键统一字符串。角色和声优星级分桶，取消星级不删除角色备注。
- 名称展示顺序保留人工修订、中文字段、条目原名，最后才编号；原名/别名继续检索。条目名已有中文时，不应被“官方暂无中文名”占位符遮住。
- 有无汉字不是官方译名认证依据；人工补名也不能标成官方。自动补齐保存来源、时间和查过的版本。
- 明确区分未查、完整、部分、成功空结果、官方无独立字段与请求失败。成功空结果可缓存；请求失败保留已有详细字段并有重试时间。
- 抓作品角色表、声优完整出演表和对象简介的完整度各自记录；“实体入库”不能代替“关系已完整”。

角色默认范围应可解释：个人作品内角色、星标角色、手动入库角色；扩展候选另有可见范围。评分/地区/范围造成的隐藏应有提示，不能显示为对象丢库。

## 3. 配音关系以本作品为锚点

基本事实为 `(subject_id, character_id, person_id)`；对语言/版本有明确证据时另保留对应字段，不从关系数组的第一位推断。

项目维护两种索引，并记录来源与完整度：

```text
by_subject[作品][角色] -> 声优集合
by_person[声优][作品] -> 角色集合
character_subjects[角色] -> 本人出演作品集合
roles_by_subject[作品][角色] -> 本作品定位
```

声优反向接口能提供“该声优—角色—作品”的记录，不能由此宣称某作品完整角色表已下载。同CV的角色集合也不能成为另一作品的角色表。主动刷新作品阵容后，应核对旧反向关系是否删除、其他作品证据是否保留。

曾出现作品详情显示其他作品角色；所选对象置顶只改变当前作品真实角色的顺序，不允许把所选声优的别作角色硬插进来。先取得本作完整阵容，再应用地区/评分显示过滤；“显示全部角色”无需重新联网，角色本人的真实出演边也不应被声优地区过滤抹掉。

## 4. CP 共演：组合条数和共同作品数分别计算

若一个角色有多个候选声优，要求明确选择，不静默取第一项。缺少完整出演来源时返回部分状态/补齐提示；地区一致也不能证明相同语言版本。

两名选定声优的作品交集产生线索，保留作品、两个角色、两个声优及来源；相同事实去重，可用 `(作品, 角色A, 角色B, 声优A, 声优B)`。同作品多组角色可以是不同共演组合，但共同作品总数按作品ID去重。不能按中文译名合并不同条目、不同季或动画/游戏。

“两名声优在同一作品有出演”不等于“官方CP”，也不自动证明跨语言版本角色在同一阵容实际共演；证据不足时明确作为共演线索。

## 5. 关联阈值与图上限

对每部作品构造支持集合 `support[作品] = {不同所选角色/声优的图ID}`。角色加入本人出演的作品；声优加入其有证据出演的作品；作品种子只作为选择对象，不给自己贡献人数。重复选择同一对象、同一声优在一作饰演多个角色均不增加人数。

明确同时选择一个角色和其声优，是两个不同所选对象；应按各自的真实作品关系计数，不能再把该声优的其他角色作品算作所选角色本人出演。

默认阈值为2；设为1时先提醒并取得该次确认，取消/关闭后输入和请求都恢复安全值。接口是否把省略阈值兼容为旧查询，需要读当前代码，不把UI默认值当成接口永远默认值。

先应用永久/临时忽略，构建真实支持集合，再按阈值选作品、保留连接证据、应用节点上限。上限不能留下“关联3人”的作品，却只保留1人的线而不说明截断。返回匹配总数、显示数和截断信息。

一个必要性质是：固定选择、数据、地区和忽略条件下，提高阈值不会增加**候选匹配作品集合**。节点上限或布局导致的可见子集变化要单独解释；勿把“当前可见节点数”当作未截断匹配全集。

回归夹具至少含：三个声优共同作品、仅两人作品、仅一人作品；重复选择；声优多角色；角色+其CV；同名不同作品；被忽略的中间桥梁；超出节点上限。若界面输入2显示1的结果，还需交错完成两次请求，排查旧响应覆盖，不能仅凭截图判定算法反了。

## 6. 人物地区与配音语言分开

明确国家/地区字段、针对本人身份的简介陈述、身份匹配的官方职业页面可以作为不同层级依据。姓名、出生地、另一位合作声优的介绍不足以单独确认。官方职业地域分类不等于法律国籍，也不等于某游戏的配音语言。

官方信息不足时，本项目允许受约束的共演辅助推断：只取完整、已缓存的动画作品，要求多部作品、多位独立已确认合作者及覆盖率/一致性门槛；具体门槛读当前 `official_regions.py` 与相关用例。排除游戏、未知类型、混合地区、多语言配音歧义；推断结果不能继续给别人推断，避免循环自证。

保存 `source/status/checked_at/evidence`，推断、官方核验、待确认分别标注。新官方资料可替换推断，未知不自动归为日本或其他。读取界面不无限触发官方检索；失败和信息不足使用不同退避。

## 7. 星标生日

只查询星级大于0的角色/声优，优先结构化生日字段，不从年龄、作品剧情或整段简介猜日期。支持月日及年月日；无效、冲突、非公历和缺失分别存状态。

缺失结果也持久化；错误按退避重试，新星标自动参与。生日页读取不被网络锁阻塞，不把作品评分/地区过滤不加说明地套到生日名单。2月29日按下一次真实闰日处理；按日历日计算距离并跨午夜更新。

典型检查：同数字ID角色/声优星级独立、零星但备注保留、缺生日不重复拉、冲突日期、闰日、跨年与时区。它们比“页面上出现生日字样”更能验证功能。
