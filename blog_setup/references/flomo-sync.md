# flomo 同步到铭记说说

用于同一个 Hexo 博客的内容同步；这是 blog-setup 的功能分支，不再单独安装 flomo Skill。脚本只用 Python 标准库，不需要网络。格式与原清洗经验见 [flomo-format.md](flomo-format.md)，旧版开发证据见 [开发案例](2026-10-29-flomo-sync-case.md)。

## 预览与应用

从技能根目录运行：

```text
python scripts/flomo_to_moment.py <项目根> --zip <导出.zip>
python scripts/flomo_to_moment.py <项目根> --zip <导出.zip> --apply
python -B tests/test_flomo_to_moment.py
```

默认只预览，不写帖子、图片、状态或日志。明确授权同步后才执行 `--apply`。不指定 ZIP 时，`moments_update/flomo_fetch/` 必须恰好一个小写 `.zip` 文件；多个包不自动选第一个。支持直接提供包路径，不必先搬进项目。ZIP 直接在内存读取，不清空原 extracted 目录，不落地解压；总内容超过 512 MiB 时停止并先评估规模。

## 身份、更新与保护

- 原文链接存在 memo_id 时用它记录身份，否则退回分钟时间戳。为保留现有地址，帖子仍用 `source/_posts/moment/YYYYMMDDHHMM.md`；同分钟多条、重复身份或跨批次身份占同一路径时整批停止，不任意丢弃记录。同一身份创建时间变化也需先确认迁移。
- `moments_update/flomo-state.json` 保存生成帖子与图片的哈希。只覆盖当前内容仍匹配上次结果的受管理文件；手工变化、外部删除、未受管理且内容不同的文件均拒绝写入。没有“强制覆盖”开关。
- 旧版文件无状态时，只有与本次完整输出字节一致才接管；图片命名/YAML 序列化变化可能导致旧文件不一致。先查看差异并备份，不能把当前手工文件随意登记为脚本生成。未完成迁移前可停止同步，不自动改写旧帖。
- 图片按内容哈希命名，避免不同导出中同名图片互相覆盖。没有图片文件或不支持的本地图片语法时先报错。远程图片保留地址、不下载，不能保证远程地址有效。
- 只增改，不删除本次 ZIP 未包含的旧帖或旧图片；报告状态中缺席记录数。没有状态的历史旧帖不在缺席计数中，不声称已识别全部历史数据。

## 验证、备份与限制

先对整批帖子、图片、冲突和受管理内容做预检，输入错误时不写入业务数据。应用时对被替换内容与旧状态保存在 `moments_update/flomo-backups/<本次ID>/`；日志为 `moments_update/flomo_to_moment.log`，记录成功应用的时间和数量。错误返回非零、向 stderr 说明，不再承诺 traceback 全部写日志。

状态、备份、导出和日志应保留在本地，不提交、不发布；不要擅自删除状态，否则失去更新基线。单文件原子替换不是整批事务或断电回滚；执行中 I/O 失败可能已写入部分文件，先核对输出、状态和备份，不盲目重跑。脚本不支持同时运行多个导入进程，运行期间不要手工修改目标文件。

自动检查只验证指定导出格式、同步和防覆盖行为，不证明图片可解码、远程地址有效或主题渲染正确。应用后核对 type/date/title/photos、正文、图片与铭记页；未做页面检查须说明。隔离测试不读取真实导出，真实博客和旧数据迁移仍待按本次任务验证。
