# 本地原稿导入普通博客文章

在用户提供 Markdown/TXT 原稿和相邻配图、希望转换为 `hexo_visn` 普通文章时读取。这里处理内容入站与本地预览；提交和推送依本次授权及 [Git 协作](git-collaboration.md) 执行。

## 导入与核对

1. 先读原稿、配图和当前同类文章，确认标题、正文、图片用途、分类及文件位置。保留原稿，不把导入当作删除或覆盖源素材的授权。正文的技术结论以作者原意为准；文字与配图不一致时指出具体差异供作者核对。
2. 按当前站点的 front-matter 与目录约定创建 `source/_posts/blog/` 下的文章。填入有依据的日期、标题、分类、标签和封面；站点模板已显示标题时，避免在正文重复原稿一级标题。不要为了获得置顶效果擅自改变其他文章。
3. 本站 `post_asset_folder: false`。将需要发布的图片复制到 `source/assets/` 下合适的文章目录，把封面与正文引用改成站点绝对路径（如 `/assets/blog/...`）。核对文件存在、图片内容与引用一致；保留输入目录。
4. 需要显示在首页最新位置时，检查实际首页生成器、现有文章的 `top` 字段和生成结果。当前项目使用 `hexo-generator-index-pin-top`：有 `top` 的文章先于无 `top` 的文章；`top` 相同再按日期倒序。`top: 300` 是 2026-11-03 这批既有普通文章的现场约定，使用前重新核对当前值。
5. 构建并检查文章路径、图片路径和首页卡片；用户要求浏览器检查时，运行 Hexo 本地服务并提供可访问链接。区分构建成功、HTTP 可达、浏览器视觉检查和远程发布；不要把前一步的结果写成后一步已完成。

本流程首次落地的现场与验证结果见 [2026-11-03 文章导入案例](2026-11-03-article-import-case.md)。
