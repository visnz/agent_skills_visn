# Hexo 博客持续维护

以当前 `hexo_visn` 项目、用户目标和实际渲染链为准。新的博客功能先归入这个入口的按需流程，开发经历另存案例；不因每完成一个功能就新建 Skill，也不提前宣称未实践的功能已经支持。

## 开始前

- 先读目标项目规则、工作区改动及相关配置，确认本次涉及内容、主题、脚本还是同步数据。保留范围外内容。
- 粗估文件量、资料装载、转换/构建和验证成本。大量媒体、批量导入或长链试错先反馈范围和方案；执行中明显扩大时暂停扩展并重新评估。
- 按下表读取当前任务所需资料，不默认加载全部流程或运行所有脚本。用户只要求检查时保持只读。

## 按任务选择流程

| 当前任务 | 读取资料与边界 |
| --- | --- |
| GIF/PNG/JPG 优化、懒加载、媒体引用 | [媒体流程](references/media-workflow.md)；参数与历史结果见其链接的转换复盘，不把一次节省比例当保证 |
| flomo ZIP 导入、说说更新或同步问题 | [同步流程](references/flomo-sync.md)，按需读格式；开发证据另见流程中的历史案例 |
| Git、仓库代理或已授权提交/推送 | [Git 协作](references/git-collaboration.md)；历史端口执行前核对，不修改全局配置 |
| 其他博客内容、主题或构建修改 | 读取实际相关配置、模板和脚本，按本次功能做最小必要修改和验证；形成新经验后再补对应参考 |

## 共同约定

- 默认保留封面 GIF 的动图意图；若当前模板或本次要求不同，依据现场调整。
- 脚本接收项目路径，不绑定作者机器。运行前检查参数、依赖与实际写入范围。媒体转换、同步、构建和发布分别授权，不把“维护博客”解释为可以任意发布。
- 不擅自清理源媒体、说说或非脚本改动。明确的导入更新按同步状态核对后执行，已有同名但不受管理的内容不自动覆盖。
- 未授权时不提交、不推送；本次已明确授权时直接按范围执行，不重复索取同一授权。
- 较完整任务收尾且有新经验时可提示一次是否按仓库规范沉淀；已经要求整理则直接完成。

## 按实际阶段验证

- 查询：说明现场发现和依据，不为查询执行转换或导入。
- 媒体：报告采用结果、跳过与失败，完成本地引用初筛及必要的页面/视觉验证；不把保留原件后的采用文件减少量称为磁盘总节省或全站 0 个 404。
- flomo：先预览计划，获准写入后用 `--apply`；核对增改/未变/接管、图片和日志，检查铭记页。手工改动、缺图、身份冲突等错误不当作成功。
- 主题/内容/构建：验证实际改动功能与生成页面；项目脚本或 filter 修改后按现场重启服务，不把生成成功等同于浏览器效果正确。
- 交付说明实际改动、验证范围、未覆盖项和 Git 状态。文件生成、浏览器检查和发布结果分别说明，未执行的阶段不声称完成。
